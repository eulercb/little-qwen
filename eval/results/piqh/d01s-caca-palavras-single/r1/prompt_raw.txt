## 1. Product

### 1.1 What it is

A word search game (caça-palavras) for Brazilian Portuguese speakers, played on a phone in portrait orientation by dragging a finger across a letter grid. It is a Progressive Web App: installable, fully offline, no accounts, no server.

The game is cozy by design: there is no timer, no score, no penalty for wrong guesses, and hints are unlimited. The only progression is completing puzzles inside themed word lists (fruits, the beach, festa junina...). The visual metaphor is a highlighter pen on paper: found words are highlighter-colored pills drawn behind the letters.

### 1.2 Core loop

1. Home screen lists themes with progress ("4 de 12").
2. Tapping a theme opens its next unsolved puzzle (12 puzzles per theme, 4 difficulty tiers × 3 puzzles).
3. The puzzle screen shows the letter grid and the list of words to find, as chips.
4. The player presses a letter and drags; the selection snaps to one of 8 directions and is drawn as a translucent yellow pill. Releasing on a listed word (read forwards or backwards) locks the pill in a color, strikes the chip, and gives a short vibration. Releasing on anything else just fades the pill out.
5. Tapping a chip pulses the first letter of that word in the grid (a hint). Unlimited.
6. When all listed words are found, a completion card offers "Próxima fase" or "Escolher tema".
7. Progress (solved puzzles, words found in the current puzzle, settings) persists in `localStorage`.

### 1.3 Explicitly out of scope

Timers, scores, streaks, leaderboards, ads, accounts, sound effects, landscape layouts, multi-language UI, a level editor, server calls of any kind, and analytics. Do not build any of these.

## 2. Stack and constraints

- Vite + TypeScript (strict), vanilla DOM, ES modules. One HTML file, hash routing.
- Unit tests with Vitest, Node environment only (no jsdom).
- PWA via `vite-plugin-pwa` (Workbox precache of the built app shell, `autoUpdate`).
- Font: Nunito (rounded, friendly, uppercase I/J/L and O/Q clearly distinct) via `@fontsource/nunito`, bundled so it works offline. Fallback `system-ui, sans-serif`.
- Target: Android Chrome first, then any modern mobile browser. Layout column max width 480px, centered; works from 320px wide.
- The grid is rendered with CSS grid for letters and an SVG overlay for pills. No canvas.
- Rendering must never depend on network availability.

## 6. Core algorithms

### 6.1 Normalization (`src/core/normalize.ts`)

Brazilian caça-palavras convention: the grid never shows accents or cedilla; the word list does.

```ts
export function normalizeWord(s: string): string {
  return s.normalize('NFD').replace(/\p{M}/gu, '').toUpperCase();
}
export function isValidWord(s: string): boolean {
  const n = normalizeWord(s);
  return /^[A-Z]{4,9}$/.test(n);
}
export function reverse(s: string): string { return [...s].reverse().join(''); }
```
`Ç` decomposes to `C` + combining cedilla, so `normalizeWord('Açúcar') === 'ACUCAR'`.

### 6.2 Seeded randomness (`src/core/prng.ts`)

Every puzzle is fully determined by its key, so the same puzzle is the same on every device and every reload.

```ts
export function hashSeed(s: string): number {           // FNV-1a 32-bit
  let h = 0x811c9dc5;
  for (let i = 0; i < s.length; i++) { h ^= s.charCodeAt(i); h = Math.imul(h, 0x01000193); }
  return h >>> 0;
}
export type Rng = () => number;                          // [0, 1)
export function mulberry32(seed: number): Rng {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
export function rngInt(rng: Rng, n: number): number { return Math.floor(rng() * n); }
export function shuffle<T>(arr: readonly T[], rng: Rng): T[] {  // Fisher–Yates on a copy
  const a = arr.slice();
  for (let i = a.length - 1; i > 0; i--) { const j = rngInt(rng, i + 1); [a[i], a[j]] = [a[j], a[i]]; }
  return a;
}
```

### 6.5 Generator (`src/core/generate.ts`)

`generatePuzzle(theme: Theme, index: number, seedSuffix = '', blocklist: string[] = BLOCKLIST): Puzzle`. Deterministic: `rng = mulberry32(hashSeed(puzzleKey(theme.id, index)))`. Steps:

1. Tier: `spec = tierForIndex(index)`. `maxLen = Math.min(spec.maxLen, spec.cols, spec.rows)`.
2. Candidate words: `theme.words` mapped to `{ display, word: normalizeWord(display) }`, filtered to `word.length` in `[spec.minLen, maxLen]` and not present (normalized) in `blocklist`, then `shuffle(..., rng)`.
3. Selection: walk the shuffled candidates and collect `spec.wordCount` words. Skip candidate W if it conflicts with any already collected V: `V.includes(W) || W.includes(V) || V.includes(reverse(W)) || W.includes(reverse(V))`. (Example: `CAFE` is a prefix of `CAFEZINHO`; `FOLIA` of `FOLIAO`; never both in one puzzle.) Keep the remaining shuffled candidates as a reserve.
4. Placement: stable-sort the collected words by length descending (long words first, shuffle order preserved among equal lengths) and place each one:
   - Enumerate every `(row, col, dir)` with `dir ∈ spec.directions` (duplicates in the list simply weight the shuffle) such that the word fits in bounds. `shuffle` the enumeration with `rng`. Take the first candidate where every cell is either empty or already holds the same letter (overlaps are welcome). Write the letters.
   - If no candidate works, drop the word and pull the next reserve word that passes the substring rule against everything already placed; try to place it in the same way. Continue until `spec.wordCount` words are placed or the reserve is exhausted.
   - At least `spec.wordCount - 1` words must end up placed; otherwise fail this attempt.
5. Fill: every empty cell gets a letter drawn with weights from `LETTER_WEIGHTS` (Appendix B) — build a cumulative table once, draw `rng()` × total. K, W and Y are absent from the table on purpose.
6. Validate the filled grid:
   - Every placed word occurs exactly once: `findOccurrences(grid, rows, cols, word)` scans all start cells × all 8 directions, collects each match as its set of cells (key = sorted `"r,c"` strings joined by `|`), and counts distinct sets. Deduplicating by cell set means a palindrome like `ARARA` read both ways counts once.
   - No word of `blocklist` (normalized) occurs anywhere, any direction.
7. If validation fails: redo step 5 only (new fill) up to 20 times; if still failing, redo from step 3 up to 10 times; if still failing throw `GenerationError`. Because the rng is consumed in a fixed order, retries are deterministic too.
8. Return `{ key, themeId, index, tier, rows, cols, grid, placements }` with `placements` in placement order.

`seedSuffix` is appended to the seed string (`hashSeed(puzzleKey(...) + seedSuffix)`). The caller (`src/ui/puzzle.ts`) wraps generation: on `GenerationError`, retry with suffixes `':1'`..`':5'`; if all fail, rethrow. With the shipped data this never happens — the test suite proves it for every theme and index.

Exports: `generatePuzzle`, `findOccurrences`, `GenerationError`, and `letterAt(puzzle, cell)`.

## 7. Selection geometry (`src/core/select.ts`)

This is the heart of the touch feel. All inputs are in grid pixel space: `(px, py)` is the pointer position relative to the top-left of the `.grid` element; `cell` is the cell size in px. The anchor is the cell where the drag started. The function is pure and heavily tested.

```ts
export interface Snap { dir: Dir | null; steps: number }
export function snapSelection(
  anchor: Cell, px: number, py: number, cell: number,
  rows: number, cols: number, prevDir: Dir | null,
): Snap
```
Algorithm:
1. Anchor center: `ax = (anchor.col + 0.5) * cell`, `ay = (anchor.row + 0.5) * cell`. `dx = px - ax`, `dy = py - ay`, `dist = hypot(dx, dy)`.
2. Dead zone: if `dist < 0.45 * cell` return `{ dir: prevDir, steps: 0 }` (selection is the anchor alone).
3. `angle = atan2(dy, dx)` in (−π, π].
4. Hysteresis: if `prevDir !== null`, compute `diff` = signed angular difference between `angle` and `angleOf(prevDir)`, wrapped into (−π, π]. If `|diff| <= 3π/16` (33.75°, i.e. the sector's own 22.5° half-width plus an 11.25° margin), keep `dir = prevDir`. Otherwise `dir = DIR_ORDER[((Math.round(angle / (Math.PI / 4)) % 8) + 8) % 8]`.
5. Steps: `unit = isDiagonal(dir) ? cell * Math.SQRT2 : cell`; `steps = Math.round(dist / unit)`; clamp to `[0, maxSteps(anchor, dir, rows, cols)]`. A pointer dragged outside the grid keeps extending along `dir` up to the edge, never further.
6. Return `{ dir, steps }`.

Also export `selectionCells(anchor, snap)` = `pathCells(anchor, snap.dir, snap.steps)` (just `[anchor]` when `dir` is null or steps is 0), and `matchWord(letters: string, remaining: Set<string>): string | null` which returns the matched normalized word if `letters` or `reverse(letters)` is in `remaining`, else null.

Sizing: a `ResizeObserver` on `.grid-area` computes `cell = clamp(floor(min(availW / cols, availH / rows)), 28, 56)` where `availW/availH` are the observed content box minus `.grid-paper` padding (8px each side). Set `--cell` and `--cols` on `.grid`, the `.grid` width/height (`cols*cell` × `rows*cell`), and the SVG `width`, `height`, `viewBox`. Re-draw all pills after a size change (recompute from cells, do not scale the SVG).

Cells: `.cells { display: grid; grid-template-columns: repeat(var(--cols), var(--cell)); position: relative; z-index: 1; }` — **no `gap`**; cells are contiguous so any point in `.grid` maps to exactly one cell by `floor(px / cell)`. `.cell { display: grid; place-items: center; user-select: none; }`. `.grid { position: relative; touch-action: none; user-select: none; -webkit-user-select: none; -webkit-touch-callout: none; }`. `.overlay { position: absolute; inset: 0; z-index: 0; pointer-events: none; }`. `.grid-paper { background: var(--surface); border-radius: var(--radius); padding: 8px; }`.

Pills: an SVG `<line>` from the center of the first cell to the center of the last, `stroke-linecap="round"`, `stroke-width = cell * 0.78`. Active drag: `stroke: var(--hl)`, `opacity: var(--active-alpha)`. Found: `stroke: var(--p<colorIndex>)`, `opacity: var(--pill-alpha)`, appended to `g.found`. Colors are assigned in the order words are found: `colorIndex = foundCount % 8`.

The `.trace` strip shows the normalized letters currently under the finger, `font-size: 22px; font-weight: 700; letter-spacing: 0.12em`. While idle it shows `STR.dragHint` until the first word of this puzzle is found, then it is empty when idle. After a successful match it shows the word for 600ms tinted with the pill color, then clears.

Chips: `.chip { border: 1px solid var(--line); background: var(--surface); border-radius: 999px; padding: 6px 12px; }`. Found: `background: var(--p<colorIndex>); border-color: transparent; text-decoration: line-through; opacity: 0.8;` and the `disabled` attribute. Chips show the display form (`Maracujá`) sorted with `localeCompare(..., 'pt-BR')`. Chip text is never uppercase — strike-through plus color means the found state does not rely on color alone.

Hint: tapping an unfound chip adds class `hint` to the cell of the word's first letter for 900ms: `@keyframes pulse { 0%,100% { transform: scale(1) } 50% { transform: scale(1.18) } }`, `animation: pulse 0.45s ease-in-out 2`, plus `box-shadow: inset 0 0 0 3px var(--hl); border-radius: 50%`. If a hint is already running, ignore the tap.

### 8.5 Pointer handling (`src/ui/pointer.ts`)

Attach to `.grid`:
- `pointerdown`: ignore non-primary mouse buttons. `grid.setPointerCapture(e.pointerId)`; `e.preventDefault()`. Compute `px, py` from `getBoundingClientRect()`; `anchor = { row: floor(py/cell), col: floor(px/cell) }`; if out of bounds, ignore. State: `{ pointerId, anchor, prevDir: null, cells: [anchor] }`. Draw the active pill from anchor to anchor. Set `.trace` to the anchor letter.
- `pointermove` (only for the captured `pointerId`): `snap = snapSelection(anchor, px, py, cell, rows, cols, prevDir)`; `prevDir = snap.dir`; `cells = selectionCells(anchor, snap)`; update the active pill endpoints and `.trace` text. Do nothing if the cell list is unchanged.
- `pointerup` / `pointercancel` / `lostpointercapture`: finalize exactly once (clear the state first so the other two events become no-ops): `letters = cells.map(letterAt).join('')`; `word = matchWord(letters, remaining)`. If found → `onFound(word, cells)`; else → miss animation: transition the active pill's opacity to 0 over 180ms, then set `display: none`.
- `onFound`: move the pill into `g.found` with its color, disable the chip, `navigator.vibrate?.(15)` when `settings.haptics`, persist progress, update `.trace`. If `remaining` becomes empty: persist solved, `navigator.vibrate?.([15, 60, 25])`, show the completion card after 350ms.

A drag that starts outside `.grid` never starts a selection. Page scroll must never happen during a drag (`touch-action: none` on `.grid`, `overscroll-behavior: none` on body, `#app` overflow hidden).

### 8.6 Completion card

Overlay `.done-backdrop` (`position: fixed; inset: 0; background: rgba(0,0,0,0.25); display: grid; place-items: center`) containing `.done-card` (`background: var(--surface); border-radius: var(--radius); padding: 24px; width: min(320px, 88vw); text-align: center`, entrance `transform: scale(0.96) → 1` and opacity over 220ms). Content: `<h2>` `STR.allFound`, `<p>` "Praia, fase 4 de 12", primary button `STR.nextPuzzle` → next index; secondary button `STR.chooseTheme` → home. If the puzzle was index 12, replace the primary button with a `<p>` `STR.themeComplete(themeName)` and keep only the secondary button.

### 8.7 Settings sheet (`src/ui/settings.ts`)

Opened from the home gear. A bottom sheet with two rows: `STR.haptics` (switch, default on) and `STR.appearance` (segmented: `STR.themeAuto` / `STR.themeLight` / `STR.themeDark`). Changes persist immediately and apply immediately. Close by tapping the backdrop or the `STR.close` button.

## 9. Persistence (`src/core/save.ts`, `src/ui/storage.ts`)

`localStorage` key: `cp.save.v1`. `defaultSave(): SaveState` = `{ v: 1, solved: [], progress: null, settings: { haptics: true, theme: 'auto' } }`. `parseSave(json: string | null): SaveState` returns the default on null, invalid JSON, wrong `v`, or wrong shape (validate each field's type; unknown fields are dropped). `serializeSave(s)` = `JSON.stringify`. `storage.ts` exposes `loadSave()`, `saveState(s)` (wrapped in try/catch — a storage failure never crashes the app) and keeps the single in-memory `SaveState` instance the UI mutates.

When to save: on every found word (`progress`), on completion (`solved` add, `progress = null`), on settings change. When opening a puzzle whose key equals `progress.key`, restore the found words: for each word find its `Placement`, rebuild its cells with `pathCells`, assign colors in stored order, and draw the pills and chips as found. Opening a different puzzle replaces `progress` on the first found word (not before — so browsing a puzzle does not lose progress on another one).
